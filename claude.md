# Firely .NET SDK notes

- If API compatibility checks fail, regenerate `/home/runner/work/firely-net-sdk/firely-net-sdk/src/Hl7.Fhir.Base/CompatibilitySuppressions.xml` with:
  `dotnet pack /home/runner/work/firely-net-sdk/firely-net-sdk/src/Hl7.Fhir.Base/Hl7.Fhir.Base.csproj -c Release /p:ApiCompatGenerateSuppressionFile=true`

## Generated code must not be edited by hand

- Every file under a `Model/Generated/` directory (`src/Hl7.Fhir.Base`, `src/Hl7.Fhir.Conformance`, `src/Hl7.Fhir.STU3`, `src/Hl7.Fhir.R4`, `src/Hl7.Fhir.R4B`, `src/Hl7.Fhir.R5`, `src/Hl7.Fhir.R6`) starts with `// <auto-generated/>` and is produced by a code generator. Never edit these files manually, not even for a one-line fix: the next regeneration silently reverts the change.
- All changes to generated classes must be made in the generator and then regenerated. The generator is the `CSharpFirely2` export language of the **fhir-codegen** project: https://github.com/FHIR/fhir-codegen, implemented in `src/Fhir.CodeGen.Lib/Language/Firely/` (main file `CSharpFirely2.cs`). Submit a pull request against that repository with the change; a Firely SDK maintainer must approve it.
- If a fix in this repository needs a change in a generated file, do not patch the generated file in the same PR. Instead, open the fhir-codegen PR, link it from the SDK issue or PR, and regenerate the files here once it is merged. If the fix cannot wait, put the hand-written code in a non-generated partial class file of the same type instead of touching the `Generated/` directory.
